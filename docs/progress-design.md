# progress.md 설계

> `progress.md`의 구조, 작성 기준, 설계 근거를 정의한다.

---

## 1. 이 파일의 역할

**progress.md는 신호 파일이다. 내용 파일이 아니다.**

면접관에게 전달하는 세 가지 신호:

1. **꾸준함** — 날짜로 증명하는 일관된 학습 이력
2. **참여 유형** — 수동 시청인지, 직접 구현인지, 디버깅인지 (유형 기호)
3. **스캔 가능성** — 30초 안에 이 사람의 학습 밀도를 파악할 수 있는가

개념의 깊이, 설계 의도, 인사이트는 섹션 README.md의 몫이다.
progress.md가 그 역할까지 맡으면 신호 기능이 약해지고, README와 중복이 생긴다.

---

## 2. 테이블 구조

```
| 날짜 | 섹션 | 내용 | 메모 | 유형 |
|------|------|------|------|------|
```

컬럼 순서는 맥락(날짜·섹션) → 내용(내용·메모) → 분류(유형) 흐름을 따른다.
유형을 마지막에 두는 이유: 행 전체를 읽은 뒤 "이날의 참여 방식"을 도장처럼 찍는 구조가 되기 때문이다.

셀 내 줄바꿈(`<br>`)은 사용하지 않는다 — 테이블의 스캔 가능성을 해친다.

---

## 3. 컬럼별 작성 기준

### 날짜

- ISO 형식: `YYYY-MM-DD`
- 복수 날짜: `YYYY-MM-DD ~ DD`

### 섹션

- 섹션 번호: `10`, `01 (복습)` 등
- 섹션과 무관한 작업(문서 정비, 포트폴리오 작업 등): `—`

### 내용

강의일과 비강의일에 따라 기준이 다르다.

**강의일 (섹션 번호 있음):**
- 학습한 개념의 키워드 나열
- 3~5개 이내, 백틱으로 코드 요소 표시, ·(가운데점)으로 구분
- 설명, 이유, 인사이트 포함 금지

```
✅ 기본 매개변수, 값·참조 전달, first-class functions, 콜백·HOF
✅ 배열·객체 구조분해, 함수 매개변수 구조분해
❌ 배열 구조분해 — 기본·건너뛰기·기본값·변수 교환, 함수 반환값에 적용; ...
```

나쁜 예처럼 세미콜론으로 이어지는 상세 설명은 README 핵심 개념 섹션에 들어가야 할 내용이다.

**비강의일 (섹션 = —):**
- 한 줄 활동 요약
- 작업 항목 나열 금지 — 가장 대표적인 활동 하나로 압축

```
✅ 포트폴리오 정비
✅ 문서 기반 정비
❌ README 전면 개편; 섹션 08 노트 이전; notes-authoring-guide 최종화; 미커밋 분리
```

### 메모

그날의 한 줄 개인 인상. **선택 항목 — 없으면 `—` 또는 빈칸.**

써야 할 것:
- 뭘 직접 구현했는가: `챌린지 3 먼저 구현 후 강의 풀이 비교`
- 뭐가 어려웠는가: `레스트와 스프레드 구분이 계속 헷갈림`
- 뭘 발견했는가: `옵셔널 체이닝이 구조분해와 세트로 쓰임을 발견`
- 에러를 직접 만났는가: `ES module CORS 에러 직접 확인`
- 어떤 작업을 했는가 (비강의일): `README 전면 개편`

쓰지 않을 것:
- 개념 설명 → 내용 컬럼 또는 README
- 여러 문장 나열 → 한 줄로 압축

### 유형

| 기호 | 의미 |
|------|------|
| 📖 | 강의 수강 |
| ✍️ | 직접 먼저 구현 |
| 🐛 | 에러·버그 디버깅 |
| 🔧 | 리팩토링·구조 개선 |
| 💬 | AI 대화로 파고듦 |

복수 가능: `📖 ✍️`, `🐛 💬`

어떤 날이 📖만인지, ✍️ 🐛 💬가 겹치는지가 학습 밀도를 한눈에 보여준다.
이 구분이 progress.md를 단순한 날짜 기록과 다르게 만드는 핵심 요소다.

## 4. 파일 섹션 구조 방침

### 과거 기록 (섹션 01 ~ 09)

현행 구조를 유지한다. **변경하지 않는다.**

이유:
- 과거 기록을 새 포맷으로 재작성하면 "원본을 수정했음"이 된다
- progress.md의 핵심 가치인 꾸준함은 앞으로의 기록으로 증명한다
- 작업량 대비 포트폴리오 효과가 없다

### 실시간 기록 (섹션 10 ~)

이 문서의 구조(5컬럼)를 따른다.
기존 과거 기록(4컬럼)과 테이블 구조가 달라도 무방하다 — 두 섹션은 성격이 다르다.

---

## 5. 설계 결정 근거

이 구조는 기존 설계와 타 학습 프로젝트의 설계를 비교·종합한 결과다.

**유지한 것 — 유형 기호:**
참여 유형을 드러내는 핵심 요소. 타 프로젝트 설계에는 없었던 부분으로,
이것이 없으면 모든 행이 동일한 무게로 보여 적극적 참여(구현·디버깅)와 수동적 참여(시청)를 구분할 수 없다.

**추가한 것 — 내용/메모 컬럼 분리:**
무엇을 배웠는가(내용)와 어떻게 경험했는가(메모)를 분리했다.
두 정보를 하나의 컬럼에 넣으면 내용이 길어지고 메모가 묻힌다.

**버린 것:**
- 내용 컬럼에 개념 설명 포함: README와 내용이 중복되고 테이블이 스캔 불가능해진다.
- `<br>` 다중 라인: 같은 이유.
- 과거/실시간 경계 강조: "초반에 일일 기록을 하지 않았음"을 드러내는 역효과가 있다.
  경계 자체는 유지하되 강조하지 않는다.
