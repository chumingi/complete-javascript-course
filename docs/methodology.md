# AI를 학습 파트너로 활용하는 방법

> 이 포트폴리오에서 Claude AI는 답을 얻는 도구가 아니라, 스스로 추론하고 검증하는 과정의 파트너로 활용된다.

---

## 문제 의식

AI에게 "이 개념이 뭐야?"라고 물으면 답은 나온다. 하지만 그 답을 읽는 것은 이해가 아니다. 내가 그 개념을 실제로 이해했는지, 어떤 맥락에서 써야 하는지, 어디서 헷갈리는지를 확인하는 과정이 빠져 있기 때문이다.

단순히 AI에게 답을 받는 것은 구글링과 다르지 않다.

---

## 이 포트폴리오에서 AI를 쓰는 방식

흐릿한 개념이 생기면 아래 흐름으로 대화를 진행한다:

1. **스스로 현재 이해를 먼저 말한다** — "내가 이해한 건 이런데, 맞나?"
2. **AI는 답 대신 질문을 돌려준다** — "그렇다면 이 경우엔 어떻게 될 것 같아?"
3. **선택지를 보며 스스로 추론한다** — AI가 제시한 시나리오를 보고 직접 판단한다
4. **추론한 결과를 AI로 검증한다** — 맞게 이해했는지, 빠진 맥락이 있는지 확인한다
5. **실무 연결점을 함께 찾는다** — "이게 React/Node에서는 어떤 모습으로 나타나?"

핵심은 AI가 흐름을 주도하지 않는다는 점이다. 내가 추론한 것을 AI가 검증하는 구조다.

---

## 실제 대화의 모습

예를 들어, 중첩 구조분해가 헷갈렸을 때:

> **나:** 중첩 구조분해가 언제 진짜로 유용한지 모르겠어. 문법은 이해했는데.
>
> **AI:** 어떤 상황에서 쓰면 유용할 것 같아? 외부에서 데이터를 받는 상황 중에 생각나는 게 있어?
>
> **나:** API 응답이 깊게 중첩된 경우?
>
> **AI:** 맞아. 그럼 그 API 응답 중간에 null이 올 수 있다면 구조분해만으로 충분할까?
>
> **나:** 아... TypeError가 날 수 있겠다. 옵셔널 체이닝이 필요하겠네.

강의에서 두 챕터에 걸쳐 따로 배운 개념이, 실무에서는 항상 세트로 쓰인다는 것을 이 과정에서 스스로 발견했다. 이 인사이트는 각 섹션의 README에 `💬 AI 대화 인사이트` 블록으로 기록된다.

---

## 이 방식이 만드는 것

- 강의를 들은 뒤 넘어가는 것이 아니라, 흐릿한 지점을 명확하게 짚고 넘어간다
- "문법을 아는 것"과 "언제 왜 쓰는지를 아는 것"을 구분한다
- AI와의 대화 자체가 학습 기록으로 남는다 — 섹션 README의 AI 인사이트 블록이 그 흔적이다
